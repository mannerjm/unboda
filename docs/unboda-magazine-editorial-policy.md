# 운보다 매거진 — 계속 운영할 때 지켜야 하는 원칙

운보다 자체 매거진(`/blog`)은 무료 사주·궁합 등 공개 정보가 필요한 이용자를 위한 **원본 설명 콘텐츠**입니다. 검색 순위를 조작하기 위한 대량 생산은 금지합니다. 운영 중인 결제/환불/고객DB/AI 상담/07시 60갑자/SNS 자동화는 독립적이며 절대 변경하지 않습니다.

## 안전한 자동 게시 경로
1. 다음 원본 주제 1개를 선정합니다. 최근 게시물 전체 `getAllMagazineReviewEntries()`의 제목·topicKey·본문과 의미 중복이면 **작성하지 않습니다**.
2. 직접 만든 **주제별 SVG 일러스트** 한 개를 `public/magazine/<slug>.svg`로 추가합니다. 외부 사진·라이선스 미확인 이미지·원격 JS·<script>·외부 URL 링크 등은 사용하지 않습니다. SVG는 1200×630이며 제목/내용과 실제 그림이 서로 맞아야 합니다.
3. `app/lib/magazine.ts`의 ARTICLES 배열에 새 객체를 추가합니다. 한글 쉽게 읽기, 4개 이상 소제목, 소제목당 실질적인 65자 이상 본문 2단락, 전체 본문 최소 700자, 독립된 생활 조언과 `/guest-saju` 등 정확히 존재하는 내부 링크가 필요합니다. 원본성/상업 사용권에 의문이 있으면 `approvedForPublication: false`로 유지하고 공개하지 않습니다.
4. 공개 승인 조건에 맞는 콘텐츠만 `approvedForPublication: true`로 포함합니다. URL은 고유 소문자 하이픈 slug, `publishedAt`은 예고한 한국시간 KST ISO 8601, `updatedAt`은 정확한 수정 시각입니다. 예약 날짜 이전에는 404 / 사이트맵·RSS 미포함, 시간이 되면 자동 노출됩니다.
5. 외부 유료 API 및 신규 과금 금지. 개인/고객 정보, 사주 확정 예언, 의학적 효능, 투자수익 보장, 무단 복제, 가짜 필자/전문가 자격, 중복 문구 대량 생성 금지. 자동 생성/보조 사용 가능성은 글 하단에 투명하게 고지합니다.
6. 변경은 **새 GitHub 브랜치와 PR**로 진행하고 먼저 `npm run test:magazine-seo`, 그다음 Vercel 미리보기 배포, Launch Security Audit와 AI Consulting E2E Contract를 모두 확인합니다. 실패 시 PR을 병합하지 않고 이미 공개된 글은 변경하지 않습니다.
7. 최초에는 주 2편(Monday/Thursday) 이내로 운영하며 실제 색인, CTR, 방문 후 무료 조회 전환 데이터를 검증한 후 횟수를 조절합니다. GSC Wizard에 유효한 사용 권한/구독이 없다면 비용 결제를 시도하거나 색인 성공을 가정하지 않습니다.
8. 승인 없이 네이버 블로그에 브라우저 매크로를 사용하거나, 네이버 계정에 로그인·원격 게시하지 않습니다. SNS 영상·글·사진·띠별운세는 전부 별도 일정 그대로 유지합니다.

## 초기에 추천하는 서로 겹치지 않는 주제
- 사주의 연주·월주·일주·시주, 각 기둥이 무엇을 나타낼까요?
- 오행 목화토금수를 쉬운 일상 예시로 이해하기
- 대운·세운은 어떻게 다른가요? 예측보다 참고로 읽는 방법
- 입춘 전후 출생연도와 띠가 혼동되는 이유
- 일간과 일주는 무엇이 다른가요?
- 가족 간 연락과 말투가 달라질 때 대화 기준 정하기
- 직장 동료와 업무 역할이 엇갈릴 때 확인할 것
- 궁합을 볼 때 비슷한 성향만 찾으면 놓치기 쉬운 것
- 재물운을 참고할 때 월간 예산을 먼저 보는 이유
- 월급날 자동결제 알림을 점검하는 작은 루틴

**운영 상태 구분:** 코드·예약 작업을 설치하는 것과 실제 검색 색인 및 계속 발행에 성공하는 것은 다릅니다. 실제 PR·배포·RSS·서치콘솔 자료로 검증된 결과만 성공으로 보고합니다.

## 별도 예약 작업 없이 운영하는 편집 재고 점검
- GitHub Actions `.github/workflows/unboda-magazine-editorial-queue.yml`은 월·목 09:17 KST 기준으로 승인된 향후 21일 공개 예정 글의 수와 날짜 게이트를 검사합니다.
- 품질 테스트/고유 slug·topicKey를 확인하고, 대기 글이 2편 미만이면 기존 매거진 관련 Draft PR 또는 동일한 미해결 Issue가 없는 경우에만 GitHub Issue 한 개를 생성합니다.
- 이 자동화는 **새 원고를 생성하거나 승인, 병합, 게시하지 않습니다.** 외부 유료 API나 ChatGPT 자동화 슬롯이 필요하지 않으며, 기존 결제·고객 기록·SNS 일정·환경 변수는 변경하지 않습니다.
- GitHub Actions 스케줄은 서비스 상황에 따라 지연되거나 생략될 수 있고, 공용 저장소의 60일 비활동 시 자동 비활성화될 수 있습니다. 정확한 영구 실행은 보장되지 않습니다.
- 무기한 신규 글 자동 *생성*은 별도의 검증 가능한 원고 생성기와 편집 승인 정책을 설계해야 하며, Google/Naver 실제 색인과 공개 기술 점검은 서로 구분합니다.

## 로컬 AI 원고 초안 생성기 (편집 승인 필수)
- `.github/workflows/unboda-magazine-local-drafts.yml`은 월·목 09:33 KST에 원본 주제 목록을 점검하고 편집용 PR이 없을 때만 주제 하나를 선택합니다. 기존 ChatGPT 예약 작업 5개에는 영향이 없습니다.
- GitHub Models는 2026-07-30 서비스 종료로 사용하지 않습니다. GitHub 공개 저장소의 표준 Ubuntu runner에서 Qwen3-1.7B-GGUF(Apache-2.0) 모델 가중치를 SHA256으로 검증하고, 고정된 llama.cpp 소스 커밋을 자체 빌드하여 **로컬에서만** 초안을 생성하도록 설계했습니다. GitHub Actions 예약 실행은 지연/누락될 수 있고 모델 다운로드·네트워크·CPU·라이선스 환경에 따라 실패할 수 있습니다.
- 대상은 `automation/magazine/draft-topic-briefs.json`의 편집 힌트가 있는 주제만이며 기존 내용과 topicKey/slug 중복 시 건너뜁니다. 주제가 소진되면 무한 재활용하지 않고 실패 처리합니다. 큐레이션된 주제 추가가 필요합니다.
- 각 원고에는 4~6개 소제목과 2개 이상의 상세 문단, 원본 SVG를 요구합니다. 과장된 예언, HTML, 외부 URL, 중복, 원본 길이 미달은 게시하지 않습니다. AI 환각·원본성의 완전 검출은 기계 검사만으로 보장되지 않으므로 사람이 검토해야 합니다.
- 초안은 **approvedForPublication: false** 로 생성되며 별도 Draft PR만 제안합니다. 이 PR을 병합해도 대외 공개·RSS·사이트맵 포함이 되지 않습니다. 담당자가 사실 확인/저작권/브랜드 점검과 별도 승인 변경을 거쳐야 공개 가능하며, 승인 전에는 무조건 비공개입니다.
- 생성 작업은 프리뷰/테스트 통과와 실제 모델 생성 성공을 분리해 확인합니다. 기존 SNS, Metricool, 결제, AI 상담, 고객·환불 DB 및 환경 변수 변경은 하지 않습니다. 새 외부 유료 텍스트 API 키는 사용하지 않습니다.
- 보안: 모델 빌드/다운로드/생성은 `contents:read` 작업에서 실행하고 Git 쓰기 권한이 있는 작업과 분리합니다. 생성된 JSON은 두 번째 작업에서 구조를 다시 검증하여 코드의 JSON 문자열 데이터로만 반영합니다. API 비밀정보나 고객 정보를 프롬프트에 포함하지 않습니다.
- 동작 특성상 **무기한 자동 공개가 아니라 지속적인 검토용 초안 제안**입니다. 장기 운영을 위해 주제 목록·원본성·독자 반응을 정기적으로 검수해야 합니다.
