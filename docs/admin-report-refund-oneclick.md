# 운보다 관리자 승인형 리포트 카드 환불 — 배포·운영

## 기본 안전 정책

- 이 기능은 기본적으로 비활성화입니다. `REPORT_REFUND_ADMIN_ENABLED=true`와 서버 전용 `REPORT_REFUND_APPROVER_IDS`(승인된 운영자 인증 사용자 UUID 목록)가 모두 필요합니다.
- 기존 관리자 인증(`requireOperator`)에 더해 이 별도 승인 목록을 검사합니다. 고객이나 비승인 고객지원 담당자는 토스 취소를 실행할 수 없습니다.
- 두 값을 설정하지 않은 preview·production에서는 버튼이 보이더라도 취소 요청을 할 수 없습니다.
- 기존 일반 고객 결제 기능, 질문권 환불·계좌송금 기능은 변경하지 않습니다.

## 운영 단계

1. `/admin/support`에서 주문이 연결된 **결제·환불** 문의를 확인합니다.
2. 문의 상태를 **확인 중**으로 저장합니다.
3. 사유를 선택하고 **원결제·중복 환불·정책 사전검사**를 실행합니다.
4. 시스템은 문의와 구매자의 실제 주문 연결, 리포트 에디션, 구매금액, 기존 환불, 결제 완료, 정책 대상, 토스 원결제 및 기존 취소를 대조합니다.
5. 승인이 가능한 건에만 근거 입력란과 **카드 전액 환불 승인** 버튼이 표시됩니다.
6. 최종 확인창에서 승인하면 서버는 같은 검증을 다시 하고 감사 기록을 영속화한 뒤 기존 `requestFullRefund`를 실행합니다.
7. Toss 전체 카드 취소가 검증되면 기존 환불 서비스가 리포트 이용권을 회수하고 `REFUND_COMPLETED`를 기록합니다.
8. 고객지원 답변을 별도로 남기고 고객에게 `/mypage/payments` 내역을 확인하도록 안내합니다.

## 절대 중복 실행 금지

- `REFUND_FAILED_RETRYING`: 자동 정산 복구 확인. 토스에서 별도 중복 취소하지 않습니다.
- `OWNER_REVIEW_REQUIRED`: 결제사와 내부 증거를 대조하고 개발 검토를 받습니다. DB를 직접 수정하지 않습니다.
- 취소 성공 후 DB 정산 오류: 기존 재조정 워커가 Toss 조회 후 내부 회수·정산을 재시도합니다. 새 취소를 하지 않습니다.
- 환불정책 V1에 따라 리포트 부분 환불, 고객 자동 승인, AI 질문권 계좌 환불은 이 기능에서 제외됩니다.
- 실거래 활성화는 별도 승인과 staging 검증, Toss 결제 테스트 후 진행합니다.

## 설정 경고

금전 취소가 발생할 수 있으므로 이 기능은 **사용자/운영자에게 알리지 않고 활성화하지 않습니다**. 최초 LIVE 실행은 테스트 거래에만 한정해 검증해야 합니다.
