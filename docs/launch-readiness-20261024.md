## 2. 정식 고객 판매 GO 전 필수 확인 (증빙 미확정)

1. **통신판매업 신고 상태 또는 적용되는 법령상 면제 근거:** 사업자 공개 사실 파일 `docs/business-publication-facts-2026-09-11.md`에는 신고번호/신고기관이 미확정이라고 적혀 있다. 대표자가 실제 신고번호 또는 면제 요건·증빙을 확인해야 하며, 숫자를 추정해 공개하지 않는다. 정부24 안내: https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=11300000006
2. **카드사 승인 및 MID:** 운영자 진술에 따르면 현대카드를 제외한 카드사 승인 완료. 실제 LIVE 승인·환불은 한 카드로 성공했지만, **현대카드 심사는 아직 완료됐다는 증빙 없음**. 토스 계약/MID의 카드사별 실제 사용 가능 상태를 상점관리자에서 확인한다. 전체 카드 승인으로 표시하거나 현대카드 결제를 보장하지 않는다. 출처: https://docs.tosspayments.com/guides/v2/deploy-checklist
3. **일반 고객 환불 처리 주체·절차:** 관리자 카드 전액 환불 API에는 주문 연결·승인자 allowlist·운영자 MFA·토스 원결제 조회·중복취소 방지가 있으나 `REPORT_REFUND_ADMIN_ENABLED=false`. 정식 판매 전 운영자 승인/MFA, 실제 지원 문의 접수 → 정책검사 → 고객 응답까지 검증해야 한다. 질문권 부분 환불·대체 환불은 별도 절차를 검증한다. 테스트용 일회성 우회를 다시 도입하지 않는다.
4. **법률·개인정보 공지 확정:** 상호·사업자 연락처가 노출되지만 개인정보 보호책임 관련 연락정보와 확정 시행일·버전, NICE 실제 계약상 처리·제공 항목, 국외 처리(미국 Vercel, OpenAI Global, 이메일 공급자, NICE gateway) 관련 법적 검토와 최종 고지가 필요하다. 기존 `/privacy`의 상세 안내가 존재한다고 최종 법무/계약 확인이 대체되지는 않는다.
5. **복구·백업:** Supabase 자동 백업/PITR 보장 범위, 백업 보유·복원 권한 및 실제 **격리 환경 복원 성공**을 확인한다. 운영 DB에서 시험 복원·파괴적 조작을 하지 않는다.
6. **실제 사용자 E2E:** 모바일/iPhone·Android, 가입부터 NICE 인증과 유료구매, 서로 다른 가족 프로필 전환 및 열람 통제, 로그아웃 뒤로가기, AI 상담 질문권 구매·차감·중도환불 및 고객지원 응답의 브라우저 검증을 마친다. 현재의 정적 회귀 테스트와 DB 조회는 이를 대체하지 않는다.

- 위 항목의 필수 증빙이 확보되기 전까지 `TOSS_LIVE_CHECKOUT_ENABLED`를 켜지 않는다.
- 현대카드 심사 미완료 상태에서는 승인되지 않은 결제수단을 지원한다고 광고하거나 보장하지 않는다. 카드사별 처리 가능 여부는 토스 측 계약과 실제 API 상태를 확인한다.

- LIVE 전체 개방은 **명시적인 최종 출시 승인**, 기준 시점 상태 점검, 검토된 GitHub PR, 성공한 보안 검사/빌드, Vercel 운영 READY 확인 순서로만 진행한다.
