# UNBODA PREMIUM REPORT GUIDE

운보다 Premium Decision Engine V3 공식 리포트 기준 문서

이 문서는 운보다의 모든 유료 심층분석 리포트가 따라야 하는 공통 구조, 품질 기준, 작성 원칙, 검증 기준을 정의한다.

모든 Premium 상품은 이 문서를 기준으로 다음 영역을 설계한다.

- Product Prompt Plugin
- Output Schema
- Parser
- Consistency Validator
- Self Review
- Safety Validator
- 결과 UI
- Analysis Asset 저장
- AI 명리 상담 연결

---

# 1. 문서 목적

운보다의 Premium 리포트는 단순히 긴 사주풀이를 제공하는 콘텐츠가 아니다.

사용자가 현재 겪는 문제를 이해하고,
왜 이런 흐름이 나타나는지 설명하며,
앞으로 무엇을 준비하고 어떤 선택을 고려해야 하는지를 돕는
AI 기반 명리 의사결정 리포트이다.

Premium 리포트의 목표는 다음과 같다.

- 사용자가 “내 사주를 실제로 분석했다”고 느끼게 한다.
- 무료 분석과 명확히 다른 깊이를 제공한다.
- 명리 근거와 현실적인 판단 기준을 연결한다.
- 막연한 조언이 아니라 실행 가능한 행동을 제시한다.
- 과장, 공포, 확정 예언에 의존하지 않는다.
- 모든 섹션이 하나의 중심 결론을 유지한다.
- 상품이 달라도 일정한 Premium 품질을 보장한다.

---

# 2. Premium Report Philosophy

운보다는 운세를 나열하지 않는다.

운보다는 사용자가 다음을 이해하도록 돕는다.

- 왜 지금 이런 일이 나타나는가
- 무엇이 핵심 원인인가
- 현재 가장 중요한 기회와 위험은 무엇인가
- 언제 흐름이 강해지거나 약해지는가
- 지금 무엇을 먼저 해야 하는가
- 어떤 선택을 보류하거나 조정해야 하는가
- 앞으로 무엇을 준비해야 하는가

유료 가치는 글자 수가 아니라 다음에서 나온다.

- 개인화된 해석
- 명리 구조의 연결
- 시기 분석
- 판단 기준
- 실행 전략
- 저장하고 다시 읽을 가치

# 3. Premium Decision Engine V3

운보다의 모든 심층분석은 다음 구조를 따른다.

```text
Core Decision Engine
+
Product Plugin
+
Product Context
+
User Context
+
Validation Pipeline

## 3-1. Core Decision Engine

Core Decision Engine은 모든 Premium 상품에 동일한 화면 섹션을 강제하는 구조가 아니다.

모든 Premium 분석에서 공통으로 보장해야 하는 것은 다음의 분석 책임이다.

- 핵심 판단
- 명리 근거
- 현재 흐름
- 변화 조건 또는 시기 흐름
- 판단 기준
- 행동 방향
- 분석의 한계

각 책임을 어떤 JSON 필드와 UI 섹션으로 표현할지는
상품 종류와 Product Plugin에 따라 달라질 수 있다.

Topic Analysis 예:

핵심 판단
→ 원인 분석
→ 명리 구조
→ 현재 상황
→ 변화 신호
→ 행동 가이드
→ 판단 체크
→ Confidence & Limits

Period Analysis 예:

기간 전체 요약
→ 기간의 핵심 명리 구조
→ 주요 변화 구간
→ 영역별 흐름
→ 활용 시점
→ 주의 시점
→ 기간별 행동 방향
→ Confidence & Limits

따라서 Executive Summary, AI Insight, Past Pattern,
Current Core Problem, AI Coach 등의 섹션은
상품 목적에 따라 유지·축소·통합할 수 있다.

3-2. Product Plugin

상품별로 분석 기준과 행동 기준을 바꾸는 모듈이다.

예(Historical Design):

MONEY
CAREER
LOVE
RELATIONSHIP
HEALTH
STUDY
BUSINESS
FORTUNE

> **CURRENT PRODUCTION**: 실제 `PremiumProductPlugin`(`app/lib/premiumProductRegistry.ts`)은
> `MONEY | CAREER | RELATIONSHIP | HEALTH | FORTUNE | COMMON` 6종이다(`LOVE` 없음).
> `STUDY`/`BUSINESS`는 Plugin이 아니라 `PaidAnalysisEngine`(`app/lib/paidAnalysisEngine.ts`) 분류다.

3-3. Product Context

같은 Plugin을 사용하더라도 상품별 질문과 범위를 구분한다.

예:

MONEY Plugin
→ 재물운
→ 투자운
→ 부동산운
→ 현금 흐름 분석

각 상품은 동일한 Plugin을 재사용할 수 있지만,
핵심 질문, 판단 범위, 행동 가이드는 서로 달라야 한다.

3-4. User Context

리포트는 가능한 경우 다음 사용자 정보를 함께 반영한다.

현재 고민
관심사
무료 분석 결과
추천 이유
기존 구매 리포트
이전 상담 내용
현재 시점

사용자 정보가 없을 경우 임의로 사건이나 상황을 만들어내지 않는다.

4. 공통 리포트 구조
SECTION 1. Executive Summary

목적:

사용자가 5~10초 안에 리포트의 핵심을 이해하게 한다.

반드시 포함:

현재 가장 중요한 판단
지금 우선해야 할 방향
리포트 전체를 관통하는 한 문장

좋은 예:

현재 재물운의 핵심은 수입을 늘리는 것보다
새는 지출과 불명확한 계약 조건을 먼저 정리하는 것입니다.

나쁜 예:

재물운이 좋습니다.

작성 원칙:

한 번에 하나의 핵심 결론만 제시한다.
모호한 긍정·부정 표현을 피한다.
Product Plugin의 핵심 질문과 직접 연결한다.
이후 모든 섹션은 이 결론을 뒤집지 않는다.

SECTION 2. AI Insight

AI Insight는 반드시 독립 섹션으로 존재해야 하는 것은 아니다.

상품 구조상 별도의 통찰이 실제로 존재할 때만 사용한다.

AI Insight가 Executive Summary,
Decision Anchor,
Current Core Problem을 단순 재서술하는 경우에는
별도 섹션으로 유지하지 않고 다른 핵심 섹션에 통합한다.

독립적인 정보가 없는데
Premium 분량을 늘리기 위해 AI Insight를 생성하지 않는다.

SECTION 3. 명리학적 근거

목적:

현재 결론이 어떻게 도출되었는지를 설명한다.

기본 연결 순서:

원국
→ 오행
→ 십성
→ 신강·신약
→ 용신
→ 격국
→ 합·충·형·파·해
→ 대운
→ 세운
→ 현재 흐름

모든 요소를 억지로 다 넣을 필요는 없지만,
핵심 결론을 뒷받침하는 실제 계산 결과를 충분히 사용해야 한다.

작성 원칙:

단순 오행 개수만으로 결론을 내리지 않는다.
특정 십성 하나로 사건을 단정하지 않는다.
용신을 행운 요소처럼 단순화하지 않는다.
대운과 세운의 방향이 같은지, 충돌하는지 구분한다.
입력에 없는 사건이나 날짜를 만들어내지 않는다.
명리 용어는 설명 없이 나열하지 않는다.
전문 용어 다음에는 현실적인 의미를 함께 설명한다.

좋은 예:

현재 대운은 활동성과 책임을 확대하지만,
세운에서는 회복과 보존을 담당하는 흐름이 약해집니다.
따라서 기회 자체는 늘어나더라도
동시에 유지 비용과 피로가 커질 수 있습니다.

SECTION 4. 과거 흐름 검증

목적:

현재 해석이 과거 흐름과 어떻게 연결되는지 보여준다.

주의:

과거 사건을 사실처럼 단정하지 않는다.

허용되는 표현:

“비슷한 흐름을 경험했을 가능성이 있습니다.”
“이 시기에도 같은 패턴이 반복되었을 수 있습니다.”
“당시 변화가 있었다면 현재 흐름과 연결해 볼 수 있습니다.”

금지 표현:

“반드시 이별했습니다.”
“그해 사고가 있었습니다.”
“그때 사업에 실패했습니다.”

작성 원칙:

계산 가능한 과거 시기만 언급한다.
최소 1개, 최대 3개 시기만 선택한다.
맞춤감을 만들기 위해 임의의 사건을 추정하지 않는다.
사용자가 직접 확인할 수 있는 질문 형태로 작성할 수 있다.

예:

지난 1~2년 사이에
일은 늘었지만 성과가 바로 남지 않거나,
책임은 커졌는데 만족감은 낮아진 경험이 있었다면
현재 흐름과 같은 구조가 반복된 것으로 볼 수 있습니다.

Past Pattern / 과거 흐름 검증은
실제 계산 가능한 과거 운 구간이 존재하고
현재 해석과 연결할 근거가 있을 때만 사용한다.

충분한 시간 근거가 없는 경우
Premium 품질을 채우기 위해 억지로 생성하지 않는다.

Past Pattern은 Optional Section이다.

SECTION 5. 현재 핵심 문제

목적:

현재 가장 먼저 해결해야 할 문제를 하나로 좁힌다.

작성 원칙:

여러 문제를 동시에 핵심이라고 하지 않는다.
성격 비판이나 운명적 결함으로 표현하지 않는다.
현재 행동과 판단에 영향을 주는 구조로 설명한다.
Product Plugin의 핵심 판단 범위 안에서 작성한다.

예:

현재 가장 큰 위험은 수입 부족이 아니라
기회가 보일 때 검토 없이 비용과 책임을 함께 늘리는 판단입니다.

SECTION 6. 변화 흐름 / Future Timeline

Topic Analysis에서는
계산 근거가 없는 고정 기간을 임의로 생성하지 않는다.

기본 구조:

현재 흐름
다음 변화의 조건
중기적으로 확인할 신호
장기적으로 준비할 방향

이 구조는 미래 사건을 예측하는 Timeline이 아니라
현재 명리 구조에서 변화가 나타날 조건과
사용자가 확인해야 할 신호를 설명하는 구조다.

"3개월 뒤", "6개월 뒤", "1년 뒤"처럼
실제 계산되지 않은 기간을
프롬프트가 임의로 고정해서 사용하지 않는다.

Period Analysis는 다르다.

올해 세운, 월운, 12개월 흐름처럼
실제로 기간 자체가 상품의 분석 대상인 경우에는
계산된 연·월·대운 구간을 시간축으로 사용할 수 있다.

이 경우에도
실제 계산된 기간 정보만 사용하며
AI가 임의의 시점을 생성하지 않는다.

SECTION 7. AI Decision

목적:

리포트 전체를 하나의 의사결정 방향으로 정리한다.

Direction 값:

확대
유지
조정
보류

Decision Anchor 구성:

decisionAnchor: {
  direction: "확대" | "유지" | "조정" | "보류";
  focus: string;
  rationale: string;
}

작성 원칙:

direction은 반드시 하나만 선택한다.
focus는 현재 가장 먼저 다뤄야 할 구체적인 대상이어야 한다.
rationale은 명리 근거와 현실 조건을 연결한다.
모든 후속 섹션은 이 방향을 유지한다.
사용자의 중요한 결정을 대신하지 않는다.

예:

Direction: 조정
Focus: 지출 구조와 계약 조건
Decision: 지금은 수입 확대보다 고정비와 책임 범위를 먼저 조정해야 합니다.

SECTION 8. Action Plan

목적:

사용자가 바로 실행할 수 있는 행동을 제시한다.

각 행동은 다음 세 요소를 포함하는 것이 좋다.

무엇을 할 것인가
+
왜 해야 하는가
+
어떤 기준으로 확인할 것인가

좋은 예:

이번 달 고정비와 반복 지출을 항목별로 정리하고,
수입의 10% 이상을 차지하는 비용부터 유지 필요성을 검토하세요.

나쁜 예:

노력하세요.
신중하세요.
잘 판단하세요.

작성 원칙:

Action Plan의 개수는 고정하지 않는다.

권장:
2~5개의 독립적인 행동.

각 행동은 서로 다른 실행 목적을 가져야 하며,
같은 행동을 표현만 바꾸어 반복하지 않는다.

행동의 개수보다
구체성, 독립성, 실행 가능성을 우선한다.
구체적인 행동 동사 사용
상품과 직접 관련된 행동만 제시
불가능한 행동이나 과도한 요구를 피함
사용자의 통제 범위 안에서 작성
금융·의료·법률 영역은 전문 판단을 대신하지 않음

SECTION 9. Avoid Guide

목적:

현재 흐름에서 피해야 할 행동과 조건을 설명한다.

작성 원칙:

Avoid Guide는 필요한 경우에만 독립 섹션으로 유지한다.

Action Guide와 의미가 거의 반대 문장으로만 구성된다면
Action Guide 내부의 "피할 것"으로 통합할 수 있다.
공포를 조장하지 않는다.
결과를 확정하지 않는다.
왜 피해야 하는지 조건을 함께 설명한다.
“절대 하지 마라”보다 판단 기준을 제공한다.

예:

조건이 불명확한 계약을 빠르게 체결하지 마세요.
현재는 기회보다 책임 범위가 뒤늦게 커질 가능성을 먼저 확인해야 합니다.

SECTION 10. Checklist

목적:

사용자가 실행 상태를 스스로 확인하게 한다.

작성 원칙:

Checklist는 Action Plan을 재서술하지 않는다.

Checklist의 역할은
실행 목록이 아니라
결정 전에 확인할 판단 조건과 검증 신호를 제공하는 것이다.

예:

- 이 선택의 책임 범위가 명확한가
- 되돌리기 어려운 조건이 있는가
- 부담과 기대 이익이 균형적인가
- 동일한 위험 신호가 반복되고 있는가

항목 수를 채우기 위해
Action Plan을 질문형으로 바꾸지 않는다.
예/아니오로 점검할 수 있어야 한다.
Action Plan과 연결되어야 한다.
모호한 감정 문장보다 실제 확인 항목 중심으로 작성한다.

예:

□ 이번 달 고정비를 항목별로 확인했는가
□ 계약 해지 조건을 읽었는가
□ 예상 비용과 최악의 비용을 함께 계산했는가

SECTION 11. AI Coach

목적:

리포트 전체를 사람다운 언어로 정리하고 실행 의지를 돕는다.

작성 원칙:

새로운 결론을 추가하지 않는다.
과도한 위로나 공포를 사용하지 않는다.
사용자의 반복 패턴을 현실적인 문장으로 짚는다.
Decision Anchor와 같은 방향으로 마무리한다.
AI Coach는 Optional Closing Section이다.

앞 섹션에 이미 충분한 결론과 행동 방향이 있는 경우
1~2문장으로만 마무리하거나 생략할 수 있다.

AI Coach는 새로운 정보나
새로운 행동 가이드를 추가하지 않는다.

앞 내용을 다른 표현으로 반복하지 않는다.

예:

당신은 기회가 보이면 먼저 움직이고,
세부 조건은 나중에 정리하는 경향이 있습니다.
이번 흐름에서는 속도보다 기준을 먼저 세우는 선택이
결과를 지키는 가장 현실적인 방법입니다.

SECTION 12. Confidence & Limits

목적:

분석의 신뢰 범위와 한계를 투명하게 설명한다.

Confidence는 예언 확률이 아니다.

다음 기준을 의미한다.

엔진 데이터의 명확성
여러 명리 요소의 일치 정도
현재 흐름의 방향성
사용자 정보의 충분성

권장 구조:

confidence: {
  level: "높음" | "중간" | "낮음";
  strongestEvidence: string[];
  uncertaintyFactors: string[];
}

작성 원칙:

숫자 확률을 임의로 만들지 않는다.
입력 정보가 부족한 경우 명확히 밝힌다.
외부 환경과 개인 선택에 따라 결과가 달라질 수 있음을 설명한다.
건강·법률·재무 영역에서는 전문 판단의 한계를 분명히 한다.

# 10. Premium Writer Standard

Premium Writer는 운보다의 모든 유료 심층분석에 적용되는
공통 글쓰기 품질 기준이다.

Premium Writer의 목적은
명리 지식을 많이 보여주는 것이 아니다.

사용자가 자신의 현재 상황을 이해하고,
왜 이런 흐름이 나타나는지 이해하고,
무엇을 판단하고 행동해야 하는지 알게 만드는 것이다.

---

## 10-1. Writer 핵심 흐름

모든 핵심 설명은 가능한 한 다음 흐름을 따른다.

현재 상황
↓
명리 근거
↓
그 근거가 의미하는 것
↓
현실에서 나타날 수 있는 모습
↓
판단 기준
↓
행동 전략

명리 근거만 설명하고 끝내지 않는다.

행동만 제시하고 이유를 생략하지 않는다.

---

## 10-2. 현실 언어 번역 원칙

명리 전문용어는 근거로 사용할 수 있다.

그러나 전문용어 자체가 설명이 되어서는 안 된다.

예:

나쁜 예

"재성이 강하고 비겁이 약합니다."

좋은 예

"돈이 움직일 기회는 커지지만,
들어온 돈을 지키는 기준이 흔들리기 쉬운 구조입니다."

전문용어를 사용할 경우
반드시 사용자가 이해할 수 있는 현실적 의미를 함께 설명한다.

---

## 10-3. AI Insight 작성 원칙

AI Insight는 리포트의 요약문이 아니다.

전체 분석에서 가장 중요한 패턴을 찾아
사용자가 자신의 상황을 새롭게 이해하도록 만드는 핵심 통찰이다.

좋은 AI Insight는 다음 질문에 답해야 한다.

1. 지금 가장 중요한 문제는 무엇인가?
2. 왜 이 문제가 나타나는가?
3. 사용자가 놓치고 있을 가능성이 높은 것은 무엇인가?
4. 그래서 무엇을 먼저 바꿔야 하는가?

AI Insight는 다른 섹션의 내용을 단순 반복하지 않는다.

---

## 10-4. Current Core Problem 작성 원칙

현재 해결해야 할 문제를 하나의 중심 문제로 압축한다.

여러 문제를 나열하지 않는다.

중심 문제는 실제 행동으로 연결할 수 있어야 한다.

예:

약한 표현

"재물 관리에 주의가 필요합니다."

강한 표현

"현재 핵심 문제는 수입 부족보다
지출과 계약의 기준이 고정되어 있지 않다는 점입니다."

---

## 10-5. Past Pattern 작성 원칙

과거 사건을 사실처럼 만들어내지 않는다.

사고, 질병, 이별, 실패, 재산 손실 등의 사건을
입력 데이터 없이 임의로 생성하지 않는다.

Past Pattern의 목적은 사건을 맞히는 것이 아니라
현재와 유사한 구조가 과거에 어떤 방식으로 나타났을 가능성이 있는지
패턴 수준에서 설명하는 것이다.

사용자가 자신의 경험과 비교하여 판단할 수 있도록 작성한다.

---

## 10-6. 행동 전략 작성 원칙

행동 전략은 추상적인 조언이 아니라
실제로 실행 가능한 수준이어야 한다.

가능하면 다음 요소를 포함한다.

- 언제 실행할 것인가
- 무엇을 할 것인가
- 왜 필요한가
- 무엇을 기준으로 완료 여부를 판단할 것인가

금지 예:

- 조심하세요.
- 신중하세요.
- 노력하세요.
- 잘 관리하세요.

권장 예:

- 이번 달 고정비와 변동비를 분리해 지출 상한을 정한다.
- 계약 전 확인할 조건을 체크리스트로 작성한다.
- 새로운 투자나 지출을 결정하기 전에 현금 보유 기준을 먼저 정한다.

---

## 10-7. Coach Message 작성 원칙

Coach Message는 앞 내용을 다시 요약하는 영역이 아니다.

사용자가 리포트를 읽은 뒤
어떤 태도와 우선순위로 행동해야 하는지를
짧고 기억에 남는 문장으로 전달한다.

과장된 위로나 희망을 제공하지 않는다.

두려움을 이용하지 않는다.

사용자의 선택권을 존중하면서
실행 방향을 명확하게 제시한다.

## 10-8. Confidence 작성 원칙

Confidence는 예언 적중률이나 성공 확률이 아니다.

현재 결론을 서로 다른 명리 근거가
얼마나 일관되게 지지하는지를 나타낸다.

Confidence에는 다음이 포함되어야 한다.

- 가장 강한 명리 근거
- 판단을 변화시킬 수 있는 현실 변수
- 분석의 적용 한계

근거가 약하면 억지로 높은 Confidence를 부여하지 않는다.

- 성공과 실패의 확정
- 질병과 사고의 단정
- 이별과 결혼의 확정
- 투자 수익 또는 손실 확정
- 사용자의 성격을 절대적으로 규정
- 불안을 이용한 구매 유도
- 명리 전문용어 나열
- 같은 결론의 반복
- 섹션마다 서로 다른 결론
- 무료 결과를 길게 다시 설명하는 방식

# 12. Premium Narrative Consistency

리포트 전체에는 하나의 중심 결론이 있어야 한다.

Premium Narrative는 특정 섹션 이름보다
다음 논리 흐름을 유지해야 한다.

명리 근거
↓
핵심 의미
↓
현재 판단
↓
변화 조건 또는 기간 흐름
↓
행동 방향
↓
판단 검증
↓
한계

상품별 Output Schema는 달라도
이 논리 연결은 유지한다.

각 섹션은 서로 다른 정보를 제공하되
동일한 중심 판단을 지지해야 한다.

앞에서는 확대를 권하고
뒤에서는 무조건 보류를 권하는 식의
상충된 결론을 만들지 않는다.

# 13. 15,000원 품질 평가 기준

15,000원 가치는 단순 분량으로 판단하지 않는다.

다음 기준을 종합적으로 평가한다.

### 이해

사용자가 자신의 현재 상황을 이전보다 더 잘 이해하게 되었는가?

### 개인화

다른 사람에게 그대로 적용할 수 있는 일반론이 아니라
해당 사용자의 명리 구조와 현재 운을 근거로 작성되었는가?

### 통찰

단순한 운세 설명을 넘어
사용자가 미처 연결하지 못했던 원인과 패턴을 보여주는가?

### 근거

핵심 결론마다 실제 명리 근거가 존재하는가?

### 행동

읽고 난 뒤 무엇을 해야 하는지 명확한가?

### 일관성

처음부터 끝까지 하나의 논리로 연결되는가?

### 가독성

명리 지식이 없는 사용자도 이해할 수 있는가?

### 저장 가치

한 번 읽고 끝나는 운세가 아니라
다시 확인하고 싶은 의사결정 자료인가?

위 기준을 만족하지 못하면
분량이 길더라도 Premium 품질로 판단하지 않는다.

Premium 분석은 분석 범위에 따라 두 종류로 나눈다.


1) Topic Analysis

특정 문제 하나를 깊게 분석한다.

예:

- 현재 관계 지속성
- 연애·관계
- 투자 성향
- 이직 판단
- 직장 내 인간관계
- 번아웃 위험
- 결혼 가능성
- 사업 확장 판단


2) Period Analysis

특정 기간 전체의 운 흐름을 종합적으로 분석한다.

예:

- 올해 세운
- 내년 세운
- 이번 달 월운
- 다음 달 월운
- 앞으로 12개월
- 10년 대운


Topic Analysis와 Period Analysis는 동일한 Premium 품질 기준을 사용한다.

하지만 두 분석을 완전히 동일한 출력 Schema에 억지로 맞추지 않는다.

Topic Analysis는
"특정 문제에 대한 판단과 행동 방향"을 중심으로 한다.

Period Analysis는
"기간 전체의 흐름, 변화 구간, 주요 영역, 주의 시점, 활용 시점"을 중심으로 한다.

공통 Core Decision Engine은 유지하되,
상품 성격에 따라 Prompt Plugin과 출력 구성을 달리할 수 있다.
