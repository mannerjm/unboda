# NICE 개인정보 사실확인 메모 — 2026-09-11

> 상태: 내부 사실확인용. 공개 개인정보처리방침 문구로 바로 사용하지 않는다.
> 목적: NICE 공식 공개자료와 현재 운보다 구현에서 확인 가능한 사실을 분리하고, 계약서/법무 확인이 필요한 항목을 명시한다.

## 1. NICE 공식 공개자료에서 확인된 사실

공식 출처:
- NICE 통합인증 서비스 가이드 v1.0.0: https://auth-guide.niceid.co.kr/
- NICE아이디 개인정보처리방침: https://www.niceid.co.kr/terms.nc?terms_type=IDPAGE002
- NICE아이디 휴대폰본인확인 소개: https://www.niceid.co.kr/prod_mobile.nc

2026-09-11 확인 기준:

1. NICE 통합인증 API 가이드는 인증 결과 복호화 후 제공 가능한 항목으로 `name`, `birthdate`, `gender`, `national_info`, `ci`, `ci2`, `di`, `ci_update`, `mobile_co`, `mobile_no`, `vnumber`, `age_code`, `auth_method`를 열거한다. 이 중 `mobile_co`, `mobile_no`는 휴대폰인증 전용 항목으로 설명되어 있다.
2. 같은 가이드는 인증 결과 데이터가 NICE와 계약된 값만 제공되며, 계약되지 않은 항목은 항목 자체가 제공되지 않는다고 명시한다. 반환 데이터 항목 추가·변경은 NICE 계약 또는 관리 담당자 문의가 필요하다고 안내한다.
3. API 가이드는 인증 결과 요청 응답에서 `enc_data`와 `integrity_value`를 받고, 이용기관이 무결성 검증 및 AES-256-GCM 복호화를 수행하는 구조를 설명한다.
4. NICE는 휴대폰 본인확인 서비스를 제공하며, 휴대폰 본인확인 처리 항목으로 생년월일, 성명, 성별, 내·외국인구분, 휴대폰번호를 고지한다. API/전문 서비스 항목에는 통신사도 포함되어 있다.
5. NICE 개인정보처리방침은 휴대폰 본인확인(전문/소켓/API 서비스)의 처리 및 보유기간을 1년으로 고지한다. 이는 NICE 측 처리/보유 사실이며, 운보다가 동일 기간 동안 동일 원문 개인정보를 보유한다는 뜻이 아니다.
6. NICE는 서비스 계약을 체결한 사업자에게 휴대폰 본인확인 결과 확인 목적으로 성명, 생년월일, 성별, 내·외국인구분, DI, CI, 휴대폰번호를 제공할 수 있다고 고지한다. NICE의 공개 개인정보처리방침에서는 이 결과 제공을 NICE 측 `개인정보의 제3자 제공` 항목으로 안내한다.
7. 실제 회원사에 제공되는 항목은 서비스/계약/설정에 따라 달라질 수 있으므로 운보다 계약 기준의 실제 반환 필드는 공개 문서만으로 확정할 수 없다.
8. NICE 휴대폰본인확인 소개 페이지는 인증 성공 시 회원사의 선택에 따라 성명, 성별, 생년월일, 내·외국인정보, 이통사정보, 휴대폰 번호, CI/DI가 제공될 수 있다고 설명하고, 회원사가 수집하는 항목은 해당 회원사의 개인정보 수집·활용 고지에 반영해야 한다고 안내한다.
9. NICE 개인정보처리방침의 국외 이전 항목은 해외 소재 사업자가 NICE와 서비스 계약을 체결한 경우의 이전을 설명한다. 이 문구만으로 운보다에 NICE 관련 국외 이전이 존재하는지 여부를 확정할 수 없다. 운보다의 실제 사업자 소재지, 서비스 경로, 계약 및 인프라 사실을 함께 확인해야 한다.
10. NICE 공개 개인정보처리방침의 위탁/재위탁 목록은 NICE 자체 업무 위탁관계를 설명한다. 이를 그대로 운보다의 수탁자/재수탁자 목록으로 복사해서는 안 된다.

## 2. 현재 운보다 구현에서 확인된 사실

1. 운보다 NICE gateway는 NICE 결과를 복호화한 뒤 `birthdate`를 이용해 한국 시간 기준 만 19세 여부만 판정한다.
2. gateway가 Vercel 애플리케이션으로 돌려주는 결과는 `adult`, `policyVersion`, `evidenceVersion`의 정규화 결과이며 원문 성명, 생년월일, 휴대폰번호, CI/DI를 반환하지 않는다.
3. Production DB의 `identity_verification_sessions`는 세션/재전송 방지/정규화 결과와 opaque provider context를 저장하며, 원문 성명, 생년월일, 휴대폰번호, CI/DI 컬럼을 두지 않는다.
4. 성공 시 계정에는 `VERIFIED_ADULT`, 방법 `EXTERNAL_PROVIDER`, 제공자 `NICE`, 정책 버전 `NICE_ADULT_19_V1`, 확인시각만 반영한다.
5. 따라서 공개 개인정보처리방침에는 NICE가 처리 가능한 전체 원문 항목과 운보다가 실제로 영구 저장하는 항목을 구분해 작성해야 한다.

## 3. 현재 확보된 계약 증거 범위

운영자 확인 기준, 현재 확보된 것은 NICE 가입 신청서와 공식 통합인증 개발 가이드 링크이며, 운보다 Client ID에 실제 활성화된 반환 필드를 별도로 확정하는 계약서/반환항목 명세는 전달받지 않았다.

따라서 다음 원칙을 적용한다.

- 공개 문구에서 운보다의 실제 반환 필드를 임의로 확정하지 않는다.
- NICE 공식 자료에 공개된 `가능한 처리/제공 항목`과 운보다가 현재 구현에서 실제로 `사용·저장하는 항목`을 구분한다.
- 운보다 앱 DB에 저장하지 않는 원문 항목을 마치 운보다가 보유하는 것처럼 쓰지 않는다.
- 향후 NICE 담당자 또는 관리 화면에서 실제 계약 반환 필드가 확인되면 이 메모와 공개 문구를 다시 대조한다.

## 4. 법적 관계와 국외 처리에 대한 현재 결론

### NICE와의 관계

- NICE 공개 개인정보처리방침은 휴대폰 본인확인 결과를 NICE와 서비스 계약을 체결한 사업자에게 제공하는 것을 NICE 측 `개인정보의 제3자 제공`으로 안내한다.
- 그러나 이 공개 문구만으로 운보다가 자신의 개인정보처리방침에서 NICE를 `수탁자`, `제3자`, 또는 그 밖의 관계 중 하나로 단정해서는 안 된다. 운보다 측의 정확한 공개 표 형식은 신청서/계약 구조와 실제 데이터 흐름을 함께 확인해 확정한다.
- 현재 공개 개인정보처리방침에는 법적 관계를 과장해 단정하는 표 대신, NICE 본인확인 이용 사실과 현재 운보다 구현의 데이터 최소화 사실을 우선 반영한다.

### 국외 처리/이전

- NICE 공개 개인정보처리방침의 국외이전 안내만으로 운보다의 NICE 흐름에 국외이전이 있다고 결론내리지 않는다.
- Production Supabase 데이터베이스는 현재 서울 리전(`ap-northeast-2`)으로 확인됐다.
- Production Vercel 배포는 현재 `iad1` 리전을 사용한다. Vercel 공식 문서상 `iad1`은 미국 워싱턴 D.C. 리전이므로, NICE와 별개로 운보다 전체 서비스의 국외 처리/이전 공개 필요성을 별도 검토해야 한다.
- NICE gateway가 동작하는 Vultr 인스턴스의 정확한 리전은 이 메모 작성 시점에 확정 증거를 확보하지 못했다.
- 따라서 공개 개인정보처리방침에 `국외이전 없음`이라고 단정하거나, 반대로 NICE 때문에 국외이전이 있다고 단정하지 않는다. 실제 제공자 법인, 이전/처리 위치, 시점·방법, 보유기간 등 공개 요건을 확인한 뒤 별도 섹션으로 확정한다.

## 5. 아직 FACT-PENDING인 항목

다음은 NICE 공식 공개자료만으로 확정하지 않는다.

- 운보다 계약에서 실제로 요청/수신하도록 설정된 반환 필드의 정확한 목록
- 운보다 측 개인정보처리방침에서 NICE 관계를 표시할 정확한 법적 분류와 표 형식
- 운보다용 표준 본인확인 창에 표시되는 동의/제공 문구의 계약상 정확한 명칭과 범위
- 운보다와 NICE 간 신청/계약에 정한 보존, 재위탁, 사고통지, 계약 종료 후 처리 조건
- 운보다 전체 서비스의 국외 처리/이전 공개에 필요한 실제 제공자 법인·위치·시점·방법·보유기간
- Vultr NICE gateway의 정확한 운영 리전

## 6. 공개 전 추가 확인할 1차 증거

아래 중 하나 이상을 확보해 실제 계약값을 대조한다.

- NICE 가입 신청서/이용계약서 중 반환항목·처리관계가 기재된 부분
- NICE 관리자/개발자 포털의 운보다 서비스 설정 화면 또는 반환항목 명세
- NICE가 운보다에 제공한 적용 가이드/동의서 표준문구
- NICE 담당자 이메일 중 실제 반환 필드, 처리관계, 보존/재위탁 조건을 확인할 수 있는 문서
- Vercel/Vultr의 실제 운영 리전과 개인정보 처리 관련 계약·DPA/하위처리자 정보

비밀키, Client Secret, API Key, 인증서 원문은 이 메모나 GitHub에 넣지 않는다.

## 7. 공개 반영 원칙

확인된 사실만으로 다음 문구는 공개 개인정보처리방침에 반영 가능하다.

- 유료 분석 구매 자격 확인을 위해 NICE평가정보의 휴대폰 본인확인 서비스를 사용한다.
- NICE 본인확인 과정에서 개인정보가 처리될 수 있고, 이용기관에 제공되는 인증 결과 항목은 계약과 설정에 따라 달라질 수 있다.
- 운보다의 현재 시스템은 결과를 일시적으로 검증·복호화하고 생년월일로 만 19세 이상 여부를 판정한다.
- 원문 성명, 생년월일, 휴대폰번호, CI/DI는 운보다 애플리케이션 데이터베이스에 저장하지 않는다.
- 계정에는 성인 인증 상태, 제공자, 정책 버전, 인증 시각 등 최소 상태만 기록한다.

반면 정확한 계약 반환 필드 목록, NICE 관계의 법적 표 제목, 국외이전 표는 사실확인이 끝날 때까지 공개 문구로 확정하지 않는다.

## 8. 현재 결론

공식 공개자료와 실제 구현을 근거로 다음은 내부적으로 확정할 수 있다.

- NICE 휴대폰 본인확인 과정에서는 본인확인에 필요한 원문 개인정보가 NICE 측에서 처리된다.
- 운보다 runtime은 현재 성인 여부 판정에 생년월일을 일시적으로 사용하지만 원문 개인정보를 애플리케이션 DB에 보관하지 않도록 구현되어 있다.
- NICE가 처리 가능한 전체 항목과 운보다가 실제 저장하는 항목은 동일하지 않다.
- NICE 공식 API 가이드만으로도 기술적 반환 가능 항목과 암호화/복호화 구조는 확인 가능하다.
- 실제 운보다 계약에 활성화된 반환 항목과 운보다 측 법적 공개 분류는 API 가이드만으로 확정할 수 없다.
- NICE와 별개로 Production Vercel 리전 때문에 전체 서비스의 국외 처리/이전 공개 검토가 필요하다.

따라서 현재 단계에서는 데이터 최소화와 실제 NICE 이용 사실을 공개 개인정보처리방침에 먼저 반영하고, 계약 필드·법적 관계·국외 처리 표는 추가 증거가 확보된 뒤 확정한다.
